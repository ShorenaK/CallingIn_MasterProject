### 7. GitHub checks — continuous integration and deployment

Create a **`.github/workflows/`** directory with a workflow such as
`quality.yml`. This is **continuous integration (CI)**: GitHub runs the
configured checks on its servers as part of the push/pull-request workflow,
adding another level of support beyond local checks.

The proposed workflow should install locked dependencies and run lint,
formatting, type checking once configured, tests with coverage, dependency
scanning, and the frontend build. Tests should not need private Atlas credentials
or write real user records. Explain the workflow before adding it.

GitHub checks run after a push or when a pull request is updated; they do not
run before a local commit. Local Husky checks run before commits. To require
passing GitHub checks before accepting a pull-request merge into main, configure
required status checks and appropriate main-branch protection/rulesets.

**Continuous deployment (CD)** would publish the application after approved
conditions are met. It is separate from CI and is not being requested for setup
now. Workflow files belong in `.github/`, not the internal `.git/` directory.

- Coverage percentages and AI reviews do not prove every behavior is correct.
