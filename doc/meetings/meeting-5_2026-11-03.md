### 3. Claude quality-review skill — frequency and best practices

I created a project-local Claude quality-review skill on
`sprint-02-authentication`. It reviews code duplication, useful documentation,
and meaningful test coverage, including success and failure paths. The skill is
invoked manually and supports changed-file and full-project review scopes.

- How frequently should I run this skill?
- What is the best practice for choosing a changed-file review versus a full
  project review?
- Should reviews happen after substantial changes, before a pull request, or at
  sprint completion? When is one review enough to cover multiple milestones?
- How should I balance AI review with automated checks and manual verification
  without repeating unnecessary work?

### 4. Saving AI coding sessions for continuity

I decided to keep curated session summaries and project-state notes in the
repository so a new chat can read the context. My goal is to reduce repeated
explanations, confusion, and hallucinated assumptions when switching chats.

- Is this a good practice for an AI-assisted software project?
- What should a handoff include, and how should I separate verified facts,
  decisions, proposals, and unfinished work?
- How should I keep notes current and make agents verify them against source
  code instead of treating old summaries as authoritative?
- What privacy, research-record, or version-control considerations should I use?
- How could I evaluate whether this practice actually improves continuity rather
  than assuming it prevents hallucinations?

### 5. Multiple agents for business operations and system maintenance

A friend showed me a workflow with multiple agents helping run a business,
including an agent delegated to check AWS services. I would like to understand
what is realistic and appropriate for Claude or another agent system.

- Can agents coordinate business operations, quality checks, AWS service
  monitoring, and detection of needed maintenance or updates?
- Which tasks can be automated reliably, and which require human review and
  approval? Is “running the whole business” a realistic goal?
- How should permissions be scoped for read-only monitoring versus changes to
  infrastructure, deployments, billing, customer data, or software dependencies?
- What logging, independent verification, cost limits, and recovery mechanisms
  would be necessary before allowing operational actions?
- Would a small supervised experiment be useful for my research, or should I
  keep it outside CallingIn's semester scope?
