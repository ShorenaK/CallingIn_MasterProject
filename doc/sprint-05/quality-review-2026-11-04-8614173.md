## Judged findings (ordered by severity)

### Should fix before the PR

**1. Medium — likely CI failure: hard-coded macOS screenshot path in a test.**
`frontend/e2e/ai-coach.spec.js:358-360` saves to
`/private/tmp/callingin-sprint05-coach-mobile.png`. CI runs on `ubuntu-latest`
(`.github/workflows/quality.yml:20`), where `/private` does not exist and a normal
runner user cannot create it, so this test will probably fail there (the CI retry
would fail the same way). It also writes outside the repo on every local run.
_Evidence:_ code + workflow reading; the CI run itself was not checked (PLAUSIBLE).
_Fix:_ use `test.info().outputPath('coach-mobile.png')`, or remove the screenshot
and keep the overflow assertion. Confirm with the GitHub Actions result for `8614173`.

**2. Medium — accessibility: focus drops to the page when generation finishes.**
`frontend/src/coach/Coach.jsx:30-41` shows **Cancel generation** only while busy.
If a keyboard user is on that button when the result (or an error) arrives, the
button is removed and focus goes to `<body>` (Probe A). Screen-reader and keyboard
users then have to start again from the top of the page. Real provider calls take
seconds, so this will happen in practice. The design says not to move focus
unexpectedly (`ai-coach-design.md:108`). The existing tests only check focus when
the response is instant.
_Fix:_ when the run ends with focus on the Cancel button, move focus to the
suggestion textarea on success, or to Generate on failure. Alternatively, keep
the button rendered and disable it with `aria-disabled`. Add a held-response
test that asserts focus.

### Worth deciding (low)

**3. Low/Medium — the original draft stops being restorable after a second apply.**
`frontend/src/coach/useCoach.js:41` replaces `previous` on every apply (Probe B).
This matches the design wording "a previous version" (`ai-coach-design.md:90`),
so it is not a contract violation. It does work against "original draft
preservation", and the user gets no warning.
_Options:_ keep the first pre-Coach text until it is restored or discarded, or
block generation while a restore is pending, or state in the UI that only one
step back is kept. Shorena's product decision.

**4. Low — pre-live hardening: the provider can still be called after the client has gone.**
`backend/src/ai-coach-provider.js:37` listens for `close` only once the call
starts. If the browser disconnects earlier (for example during the account
lookup), the event has already fired. `generate` then still runs, until it
finishes or 20 s pass, and the result is thrown away (`ai-coach.js:75`). With a
mock this costs nothing. With OpenAI it is a paid call nobody receives.
_Evidence:_ code reading only, not reproduced.
_Fix:_ before dispatching, check whether the response or socket is already
destroyed, and add one backend test for it.

**5. Low — Coach controls appear after the session has ended.**
`frontend/src/invitations/SendInvitation.jsx:34-38` renders `<Coach>` next to the
read-only retained draft after a lookup 401. `coach.reset()` always runs before
this point, so the Coach is empty but **Generate** still works. In that state, a
successful apply would also change the "unsent message" the user was told to copy.
_Fix:_ remove `<Coach>` from this branch, or render it read-only.

**6. Low — every failure shows the same message.**
`frontend/src/coach/useCoach.js:123-131` gives 422, 429, 502, 503 and 504 the same
"try again" text. 503 is the normal state today, and the design's 429 row
(`ai-coach-design.md:146`) asks for a safe retry delay. This becomes more
important once a daily budget exists.
_Fix:_ use separate copy for unavailable and for too-many-requests (shown with
`Retry-After`). Can wait for the live step.

**7. Low — keyboard return point after Change person → Keep writing.**
`SendInvitation.jsx:185-188` sends focus to **Cancel**, not back to **Change
person**, the button that opened the confirmation. _Fix:_ remember which button
opened the confirmation and return focus to it.

**8. Low — the 5,000 limit is written in several places.**
`backend/src/ai-coach-policy.js:9-15` repeats `validInvitationMessage`
(`invitation-policy.js:19-23`) with a literal `5000`. `frontend/src/coach/api.js:7-9`
also uses `5000` instead of `MESSAGE_MAX`. If the invitation limit changes, the
Coach limits will drift from it. _Fix:_ reuse the existing constant/validator.
No new abstraction is needed.

  rule as invitations, and allows 5,000 trimmed UTF-16 units. Output gets the same
  check and is shown only in a textarea.

  with no provider error or user text. Responses are `no-store`.

  reset, and unmount. Send is blocked while generating. Nothing sends
  automatically. Text is kept on 401 with an explicit Sign in again.
