### Looked correct (reviewer reading)

- **Opening:** only the sender or recipient of an `accepted` invitation can open
  (`conversation-opening.js:77-90`). Outsiders and missing invitations share a
  404, and other statuses return 409. `$setOnInsert` upsert, the unique index
  (`conversation-storage.js:77-82`), and duplicate-key recovery (`:38-48`) give
  one room per invitation.
- **Authorization:** `requireConversation` filters by room ID and current
  account on every message and partner-status request (`conversation-access.js:19-25`).
  Routes mount behind session, `requireAccount`, and request protection
  (`app.js:53,70`).
- **Sending:** the body must be exactly `{ text }`. Sender, room, ID, and time
  come from the server (`messages.js:41-47`). Trimmed text has 1–5,000 UTF-16
  units with visible content. The 16 KB JSON limit is separate (`app.js:54`).
  The database validator (`message-storage.js:9`) is looser than the server
  check, so it is a backstop only.
- **Pagination:** newest first, 20 by default, 1–50 allowed. Unknown or repeated
  parameters are rejected. The cursor is a strict ISO-time~ID round-trip, and the
  room filter always applies (`messages.js:70-77`, `message-pagination.js`).
  Equal timestamps are broken by `_id`, matching the index (`message-storage.js:71`).
- **Rate limit:** 60 attempts per account per minute, mounted before the room
  check, so rejected attempts count (`app.js:83-88`). Process-local, as the
  documentation says.
- **Stale responses:** the opening request is ignored after unmount
  (`useConversation.js:18-31`). History and older pages use a generation counter
  that refresh and unmount advance (`:53-105,121-150`). Replies ignore results
  after unmount (`useReply.js:15-20,36,41`). Refresh is disabled while a send is
  pending (`Conversation.jsx:84`), so a send cannot be overwritten by a refresh.
- **Drafts and expiry:** the reply stays in memory and becomes read-only and
  focused on expiry (`Conversation.jsx:303-316`). Sign-in is explicit
  (`:237-243`). Leaving with any text (whitespace included) asks for
  confirmation, and a pending send blocks leaving (`useConversationLeave.js:22-29`).
  Invitation drafts stay mounted because the invitation lists are only hidden
  (`Invitations.jsx:47`). A retained invitation draft still waits for its own
  Sign in again (`useSendInvitation.js:39`).
- **Fixed since `fd0b855`:** the first history load no longer stays in loading on
  expiry (`useConversation.js:133-139`, test `conversation-resilience.spec.js:336`).
  Invisible-only text is rejected on both client and server (`828ea32`). The
  partner panel no longer shows a second expiry alert (`PartnerBattery.jsx:16`).
  The Busy colour was changed by `44ef40b`.
